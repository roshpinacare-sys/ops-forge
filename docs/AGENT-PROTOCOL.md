# פרוטוקול-נחיל הסוכנים (v1 — T37)

**ההנחה של הבעלים:** הוא מפעיל כמה סוכנים מקבילים כמוני, ושולח לכולם את אותן-הוראות. אין בינינו תקשורת-ישירה — **ה-Git הוא ערוץ-התקשורת היחיד**. מטרת הנחיל: לייעל אחד את השני ולהוציא תוצאות-חריגות, בלי דריסות ובלי כפילויות.

---

## 1. פתיחת-סשן (חובה לכל-סוכן, בכל-סשן — גם אחרי מוות)

1. **אודיט-ניתוק:** `git status/log` מקומי · תהליכים חיים · tail של dev.log · PAT + ראשי-ריפו-אמת (intake/forge/GridWatch/FleetHQ) · מצב-צי/תור.
2. **קריאה:** `worklog.md` (הקצה-האחרון) · `docs/MASTER-PLAN-001.md` · `t36/GAPS.md` · `docs/protocol-canon.md`.
3. **דה-דופליקציה:** השוואת trace_id מול worklog — אסור לחזור על עבודה-שנעשתה; העבודה-הקיימת נחשבת נכס, לא איום.
4. **תפיסת-מסלול:** בחירת GAP פנוי מ-t36/GAPS.md ורישום-שם + Task-ID מתחתיו — בעלות-יחידה-בכל-רגע.
5. **תכנון-לפני-ביצוע (L-02):** אפיק → תוכנית-קצרה ב-worklog לפני שורת-קוד.

## 2. כללי-ביצוע

- **קוד-נקי (L-04):** רק קבצי-המסלול שלך / קבצים-חדשים; אפס נגיעה בקבצים-זרים; הסגר-זיהום (רעש-chmod, tmp/, `--width`); `git config core.fileMode=false`.
- **כנות:** מה שלא נמדד — לא מוצג; כפתור-שלא-עובד — לא קיים (L-05); ריק-כנה מוצג כריק.
- **אימות-חובה לפני סיום:** דפדפן 1440+390 (sw==cw · אפס-overflow · אפס-שגיאות-קונסולה · מטרות ≥44px) · lint 0/0 · mech-selftest · dev.log נקי.
- **כתיבות-ענן:** pre-flight + readback MD5/SHA-חובה (L-06); אפס-סודות ב-Git — מפתחות רק בכספת/Actions (חוק-T31).

## 3. ייעול-הדדי — המנוע של "תנסו לייעל אחד את השני"

- סוכן שמזהה שיפור בעבודת-חבר כותב ב-worklog סעיף:
  `OPTIMIZE-PROPOSAL: <Task-ID-החבר> — <השיפור> — <המדידה-התומכת>`
- הסוכן-הבא שנוגע באותו-תחום **מחויב**: לאמץ (עם-קרדיט) **או** להפריך (עם-מדידה-נגדית). התעלמות = הפרת-פרוטוקול.
- הצעות מאומצות משולבות לגרסת-על של MASTER-PLAN-001 (append-only; גרסאות v1→v2).

## 4. מוות-וריבונות

- הסוכנים ארעיים; **ה-Git הוא הריבונות.** כל-תוצר חייב: commit מקומי + מירור לריפו-אמת (MASTER-PLAN §4-D3).
- הקמה-מחדש תמיד מ-Git בלבד לפי `docs/COLD-START.md` (Phase D1) — סוכן-חדש = אודיט → קריאה → תפיסת-GAP → תכנון → ביצוע → קבלה.
- קבלות הן הוכחת-החיים של המערכת: כל-סיום-משימה → RECEIPT עם שדה `externalValue` (L-03).

## 5. פורמט-worklog (קיים, נאכף)

```text
---
Task ID: <מזהה>
Agent: <שם-הסוכן + trace_id>
Task: <מה התבקש>

Work Log:
- <צעד-מדידה>

Stage Summary:
- <תוצרים/החלטות/קומיטים>
```

+ סעיפי `OPTIMIZE-PROPOSAL:` לפי סעיף 3.

## 6. סדר-עדיפויות-נוכחי (מצביע ל-MASTER-PLAN §4)

**A (אמת-כספית) → B (שער-ערך+ארנק) → C (הבלוקצ'יין שלנו — המוקד) → D (ריבונות-עצמאית) → E (ממשק-ענקים)** · SP = תעלת-נתונים-שולית בלבד (L-01).
